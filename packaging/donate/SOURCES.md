# 打赏收款码（构建输入）

本目录存放**随包分发**的两张收款码（作者的支付宝与微信）。

| 文件 | 平台 | 尺寸 | 体积 |
|------|------|------|------|
| `zfb.jpg` | 支付宝 | 480×720 | 60 KB |
| `wx.jpg` | 微信 | 480×654 | 41 KB |

## 为什么是压缩过的

原图是 1080×1620 / 1283×1748 的照片级 JPEG（共 295 KB），界面里只按 220px 宽显示。
one-folder 体积贴着闸门（212.12 MB / 213 MB，只剩 0.88 MB），所以压到 **480px 宽 + JPEG q85**
（显示尺寸的 2 倍多，够高 DPI；二维码容错率高，不影响扫）。

## 怎么重新生成

原图**不在仓库里**（在作者本机）。改压缩规格或换收款码时：

```powershell
python scripts\make_donate_qr.py --zfb <支付宝原图> --wx <微信原图>
python scripts\make_donate_qr.py --check      # 校验产物符合规格
```

产物入库（与 `packaging/icon/app-icon.ico`、`packaging/fonts/*.ttf` 同一惯例），
所以构建机与 CI 不需要原图。`tests/test_donate.py` 会守住「宽度 ≤480 且单张 ≤80 KB」。

## 注意

- 收款码本身是**公开信息**（就是要给人扫的），但它一旦进公开仓库就会留在 git 历史里。
  这是作者的知情选择：换码需要改历史或直接覆盖新文件。
- 界面里写明「**完全自愿，不影响任何功能**」，避免被理解成收费软件。
